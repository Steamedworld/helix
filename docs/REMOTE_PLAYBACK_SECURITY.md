# Remote Playback Security

Helix supports two modes for playing media from a Trusted Home: **proxy playback** (recommended) and **direct playback**.

## Proxy playback

The local Helix server fetches the media stream from the source home and relays it to the browser. The browser never communicates with the remote home directly.

Security properties:
- The federation token is stored server-side only, encrypted at rest. It is never sent to the browser.
- The upstream URL is constructed from the stored `base_url` of the node — the browser cannot influence it (SSRF prevention).
- Only safe headers (`content-type`, `content-length`, `content-range`, `accept-ranges`) are forwarded from the upstream response to the browser. All other upstream headers — including `authorization`, internal headers, and `server` — are stripped.
- Proxy playback failures are recorded as a safe diagnostic code (`remote_unreachable`, `remote_unauthorized`, `range_failed`, `unknown`) — never including the upstream error body, stack trace, or the federation token.

## Signed refresh tokens

For remote media, the player receives a short-lived signed refresh token (`?rt=`) in the playback source. This token:
- Is signed with HMAC-SHA256 using a server-side secret (`TRUSTED_HOME_PLAYBACK_REFRESH_SECRET`).
- Contains the user ID, session binding, node ID, and media ID — scoped so it cannot be reused for a different item.
- Rotates on every refresh (new nonce, new iat/exp).
- Has a short TTL (default 3 minutes). Clients refresh it proactively before expiry.

The token is **not** the federation token — it authorizes the browser to request a new playback URL from this home's own API. The federation token never leaves the server.

## Direct playback

In direct mode, the browser fetches the media stream from the source home directly using a signed, time-limited URL. The URL is served via the source home's `/api/v1/federation/media/:id/stream` endpoint.

Security properties:
- The signed URL has a limited TTL (`MEDIA_TOKEN_TTL_SECONDS`, default 4 hours).
- The URL is scoped to a specific media file and a synthetic federation caller identity.
- Direct playback requires the source home's `BASE_URL` to be reachable from the user's browser. If the source home is on a private/loopback address, the browser typically cannot reach it — a warning is shown.

## Federation token lifecycle

1. Generated by admin via `POST /api/v1/federation/token` — random 256-bit hex.
2. Stored as a SHA-256 hash in the `nodes.federation_token_hash` column.
3. Sent by remote homes as `Authorization: Bearer <raw-token>` on federation endpoints.
4. Verified with `timingSafeEqual` to prevent timing attacks.
5. Revocable at any time via `DELETE /api/v1/federation/token` — immediately invalidates all calls from that token.

## Limitations

- Proxy playback requires both homes to be online simultaneously.
- Direct playback requires the source home's address to be reachable from the user's browser — this may not work across NAT without a VPN or reverse proxy.
- Helix does not provide relay, NAT traversal, or transcoding for remote streams.
